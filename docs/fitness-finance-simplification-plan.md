- 最新执行顺序：按用户要求先删除前后端功能，最后清理数据库；不以数据库前置问题阻塞本地可回退代码清理。

## 1. 最终目标

Life OPS 只保留健身与财务两块业务，提供网页查看、必要备用操作，以及供笔记系统调用的 CLI/API。

彻底移除废弃业务的页面、组件、专属 API、数据库对象、云函数、实验运行时与无用依赖。保留必要公共基础设施、历史迁移来源和私有恢复归档，不重写 Git 历史。

用户已明确保留时间节奏、本月剩余、年度剩余。根地址默认进入现有健身页作为本方案暂定默认，不新建综合首页。

## 2. 保留范围

| 层级 | 保留 |
| --- | --- |
| 业务 | 健身、财务现有查看、统计、筛选、录入与编辑能力；现有健身录入缺口修复后验收 |
| 网页入口 | /fitness 及子页、/finance、/settings、/developer |
| 公共能力 | 登录、回调、会话、财务访问验证、主题、时间卡片、布局控制、必要 UI |
| CLI | packages/cli、cli-api、全部现有 /api/v1/*、/cli/authorize、设备授权与撤销 |
| 数据库 | 3 张健身表 + 8 张财务表 + 4 张 CLI 表 + system_configs 中训练部位配置，共 16 张表 |
| 数据库函数 | cli_claim_idempotency_key、cli_log_fitness_workout、finance_set_updated_at |
| 平台 | Supabase Auth、必要索引/约束/权限、备份恢复、web 与 CLI workspace |

具体表名、函数签名和兼容字段以审计清单为准。财务分类 family、childcare 仍属于财务业务，保留；不因模块名称相似而删除相关交易。

## 3. 最终界面

- 左侧只保留健身、财务；顶部保留设置、主题和左右面板收起按钮。
- 右侧保留时间节奏、本月剩余、年度剩余；统一年度剩余比例文案。
- 移除待办数量、家庭待办、今日英语、输出快捷入口和待办查询。
- 第一版不增加动作库、训练录入等常驻快捷按钮；它们保留在对应业务页面内。验收时如确实难以到达，再增加有明确用途的快捷入口。
- 设置只保留训练部位、动作管理和开发者访问链接。财务设置继续在现有财务页面内。
- 删除旧命令中心，不再把 /commands 收进设置。命令中心是模板管理，不是 CLI。
- 删除旧模块路由，旧 URL 返回 404；删除旧首页组件及无关主动预加载，不留下永久隐藏模块。
- 保留现有布局偏好，不增加新导航框架或偏好系统。

## 4. 删除范围

### 应用代码

删除 features 下 dashboard、daily-frogs、daily-til、growth-projects、quick-notes、output、english-learning、english-prompts、prompt-library、family、youyou、search、timeline、command-center，并删除对应 app 路由及专属测试/样式/文档入口。

system-config 按保留范围直接裁剪，不再增加“其他模块配置”折叠区或为废弃配置实现按需加载。

移除 harness/core、api、ui、dev、sql 及其 workspace/dev 启动配置；私有运行记录与环境文件先归档。清理专属包依赖与无引用公共组件，更新 lockfile。保留现有 Next.js、Supabase、React Query、web + CLI workspace，不同时更换技术栈。

### 数据库与云资源

- 删除审计列出的 28 张废弃业务表、2 个 analytics 视图、5 个废弃函数，以及专属触发器、索引与策略。
- system_configs 只删除已列出的废弃 scope 行，保留 exercise_category；新出现的未知 scope 先重新归类。
- 下线线上 ai-english、ai-english-summary；清理本地源码与确认不再使用的专属 Secret。
- avatars bucket 当前仅发现又又模块代码消费，完成对象用途核对和独立文件导出后清理。
- 不删除 auth/storage 等平台 schema 或平台扩展。harness SQL 草案对象线上未部署，不编造对应 DROP。
- 发布前核查外部任务；本次数据库目录未发现 cron.job，不代表其他调度器不存在。

## 5. 前置问题与完成门槛

| 问题 | 已核实事实 | 实施前要求 |
| --- | --- | --- |
| 迁移漂移 | 本地与线上有 2 组同名异版本迁移，1 个本地账户种子迁移无线上对应记录 | 比对实际 SQL/schema，建立可靠版本映射；不盲目重放 |
| 初始化基线不足 | migrations 未找到健身三表初始建表；旧迁移含单用户回填/空表重建前提 | 分别验证新环境初始化及现有库升级，不以空库重放成功作未经验证的前提 |
| 备份未核实 | README 所指本机备份目录、脚本和 LaunchAgent 未找到 | 找到或建立实际备份，验证恢复；保存不受滚动清理影响的删除前归档 |
| 网页备用录入缺口 | 新建 workout session 未传线上必填 user_id | 在隔离环境修复并验证新日期创建、同日追加、编辑与查询归属 |
| 健身权限缺口 | 健身三表 RLS 未开启且 anon 有表级读写授权 | 核对 Data API 暴露情况，修复归属与权限；分别设计训练数据和动作库权限 |
| 私有文件 | avatars 含 1 个对象；数据库 dump 不包含对象文件 | 单独归档文件并核对引用，不将私人照片或账单放入 Git |

上述表格保留原审计基线；健身权限及录入问题现已通过独立修复解决，详见[修复结果](audits/2026-09-07-fitness-security-fix-results.md)。新环境初始化及旧迁移漂移仍需后续处理。

## 8. 回退界限与停止条件

- 数据库删除前：精简应用仍使用保留的旧 schema，可回退代码；核心权限修复单独评估兼容性。
- 数据库删除后：旧版本应用可能依赖已删对象，不能仅回退代码。先向隔离环境恢复归档，再选择性恢复旧对象，保护删除后新写入的训练与财务数据。
- 遇到未知跨模块依赖、无可恢复备份、迁移版本不明、保留数据对照异常，停止生产删除，保留已完成的可回退工作。
- 最终持续维护范围是健身、财务和必要支撑能力；不再维护旧业务的可运行入口。
